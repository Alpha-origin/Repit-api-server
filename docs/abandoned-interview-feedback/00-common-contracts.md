# 00. 공통 정책과 계약

상태: 구현 설계안. 기준 커밋은 [README](README.md)를 따른다.

## 1. 적용 범위

SOLO/MULTI, 텍스트/음성 답변, 기업 선택 유무에 같은 정책을 적용한다. 중단은 **서버가 ABANDONED로 확정한 종료**다. 단순 소켓 끊김을 즉시 중단으로 간주하지 않는다. 텍스트 피드백·companyFit뿐 아니라 중단 면접의 자동 음성·영상 분석과 수동 재분석도 차단한다. 녹화 업로드·기록 보존과 분석 실행을 분리한다. 별도 보관·삭제 정책은 변경하지 않는다.

| 상황 | 면접 상태 | 피드백·미디어 분석 |
|---|---|---|
| 기존 질문 진행이 끝나 정상 종료 | COMPLETED | 기존 조건 충족 시 허용 |
| 나가기·헤더 이동·뒤로가기·로그아웃에서 QUIT 접수 | ABANDONED | 생성·재시도 금지 |
| 일시적 단절·소켓 재연결 | 기존 상태 유지 | IN_PROGRESS면 미실행 |
| 새로고침·강제 종료로 QUIT 전달 실패 | 임의로 완료 처리하지 않음 | 완료 확정 전 금지 |
| 이전 중단 면접·대기 작업 | ABANDONED | 재실행·결과 노출 차단 |

브라우저 강제 종료 시 QUIT 전달을 100% 보장하는 새 만료 정책은 추가하지 않는다. 서버의 기존 세션 만료만으로 COMPLETED를 만들지 않는다. 면접 시작 시 질문 세트를 사용 처리하는 기존 결정도 유지한다.

## 2. 상태 전이와 경합

기존 enum `IN_PROGRESS`, `COMPLETED`, `ABANDONED`를 유지한다.

- IN_PROGRESS → COMPLETED: Chat이 기존 질문 진행 종료를 확인한 경우만 허용한다.
- IN_PROGRESS → ABANDONED: QUIT를 수락하면 확정한다. 답변이 하나라도 있다고 COMPLETED로 바꾸지 않는다.
- 이미 확정된 종료 상태는 반대 요청으로 바꾸지 않는다. 먼저 확정된 상태가 이긴다.
- COMPLETED 뒤 늦은 QUIT는 기존 COMPLETED 결과를 반환한다.
- ABANDONED 뒤 늦은 COMPLETE·ANSWER·END는 ABANDONED를 유지한다.
- 기존 진행 상태로 완료를 판정한다. 모든 답변이 비어 있지 않아야 한다는 새 규칙·점수 기준은 만들지 않는다.

Chat은 `InterviewOperationLock`과 outbox를, API는 `claimResultSave` 조건부 갱신을 재사용한다. 잠금 밖에서 읽은 값으로 최종 상태를 덮어쓰지 않는다. API는 중복 result 수신 시 **요청 status가 아닌 저장된 최종 상태**로 후속 실행을 결정한다.

## 3. Chat → API 기록 저장

기존 `POST /api/interviews/result`와 요청 `status`를 재사용한다. 신규 결과에는 COMPLETED 또는 ABANDONED를 명시한다. 별도 feedbackRequested 불리언은 만들지 않는다.

- ABANDONED도 질문·이미 접수한 답변·면접관·기업 스냅샷 참조를 보존한다.
- 신규 종료 요청 status 누락/null/IN_PROGRESS는 422다. COMPLETED 자동 보정을 제거한다.
- 이미 최종 기록이 있으면 기존 멱등 정책으로 응답하고 기록·질문 PK를 재생성하지 않는다. 식별·인증 검증은 생략하지 않는다.
- 상태 형식 강화 전에 이전 outbox에 상태 누락 payload가 있는지 조사한다. 답변 개수로 일괄 완료 처리하지 않는다.
- 중단 기록 저장 성공은 2xx다. 분석 생략 때문에 오류를 반환하여 outbox를 재시도시키지 않는다.

REST는 기존 `ChatProgressResponse.status`를 유지한다. WebSocket END에는 status를 추가한다(신규 제안). 새 이벤트 타입은 만들지 않는다.

```json
{ "type": "END", "status": "ABANDONED", "message": "면접이 중단되었습니다" }
```

정상 완료는 END의 status=COMPLETED다. END 문자열만으로 완료를 판정하지 않는다. 확정 상태 없는 구 END는 기존 상태 조회·진행 중 종료 요청의 응답으로 확인하고 피드백 생성에 바로 연결하지 않는다.

## 4. API 실행 정책

API 저장 상태 `interview.status == COMPLETED`만 분석 실행 자격을 갖는다. 기존 소유권·내부 호출 인증 뒤 상태를 판단한다.

| 호출 | ABANDONED | IN_PROGRESS |
|---|---|---|
| 자동 생성·sweep·업로드 후 재검사 | 정상적인 정책 생략 | 미실행·보류 |
| 수동 생성·재채점·음성/영상 재분석 | HTTP 409 | HTTP 409 |
| 피드백·분석 단건 조회 | HTTP 409 | HTTP 409 |
| 피드백 목록·이전 점수 비교 | 제외 | 제외 |
| 면접 목록·기록 조회 | 기존 권한하에 보존 | 기존 정책 유지 |
| 기록·녹화 업로드 | 보존 정책 유지, 분석 미실행 | 저장 가능, 분석은 완료까지 보류 |

409 메시지 예: `중단된 면접은 피드백을 생성하지 않습니다` / `완료된 면접만 피드백을 요청할 수 있습니다`. 기존 오류 envelope를 유지하고 새 error code 필드 추가를 전제하지 않는다. 완료 면접의 질문·답변 부족, 분석 장애, 중복 작업의 오류 코드는 기존 정책을 유지한다.

## 5. API → Analysis 텍스트 피드백 계약

기존 `/feedback/solo`, `/feedback/multi` 요청 최상위에 필드를 추가한다. 아래는 추가 필드만 보여 주며 기존 필수 필드는 그대로 보낸다.

```json
{ "interviewStatus": "COMPLETED" }
```

- API가 저장 상태를 검사한 뒤 직접 채운다. Web 입력을 복사하지 않는다.
- Analysis 강화 후 필수이며 COMPLETED만 허용한다. 누락/null/ABANDONED/IN_PROGRESS/알 수 없는 값은 동기 422다.
- 검증 실패 시 jobId 발급·BackgroundTasks 등록·LLM·기업 코멘트·콜백 모두 0회다.
- 수신 경계에서만 검증하고 채점 프롬프트·점수 계산에 넣지 않는다.
- Analysis는 API DB를 새로 조회하지 않는다. 접수 상태 선언이 API의 실제 저장 상태 검사를 대체하지 않는다.
- `/analysis/audio`, `/analysis/video` 원격 계약에는 필드를 추가하지 않는다. 자동·수동·복구·재전송 직전에 API가 자격을 강제한다.

API가 필드를 먼저 보내고 모든 인스턴스 전환을 확인한 후 Analysis에서 필수화한다. 누락을 COMPLETED로 기본 처리하는 우회는 만들지 않는다.

## 6. 대기 작업과 늦은 콜백

- dispatch에 정책 생략 종료 상태 `SKIPPED`를 추가한다(신규 제안). ABANDONED의 WAITING·만료 SENDING을 사유 `INTERVIEW_ABANDONED`로 닫는다.
- IN_PROGRESS 대기를 영구 SKIPPED로 닫지 않는다. 완료 후 실행 가능해야 한다.
- 기존 Feedback/Audio/Video 작업 enum은 추가하지 않는다. 중단 면접의 과거 PENDING은 기존 FAILED와 정책 사유로 정리하고 조회·재시도에서 제외한다.
- 과거 중단 성공 결과는 자동 삭제하지 않는다. 새 조회·목록에서 제외한다.
- 늦은 콜백은 식별·권한 검증 뒤 알려진 비대상 작업이면 2xx로 수신 종료하되 결과·항목·기업 코멘트를 생성/갱신하지 않는다. 미확인·위조 요청을 무조건 성공 처리하지 않는다.
- 결과 저장 트랜잭션 안에서 상태를 확인한다. 조기 콜백 복구가 새 피드백 행을 만드는 경로도 차단한다.
- 기존 원격 모델·미디어 작업의 물리적 강제 중지는 보장하지 않는다. 완료 결과가 다시 노출되지 않게 한다.

## 7. 완료 불변 조건

1. 신규 ABANDONED의 자동/수동 텍스트·기업·음성·영상 분석 요청 수는 0이다.
2. 대기·복구·콜백·업로드가 와도 중단 면접에 생성 대기 화면·결과 카드가 생기지 않는다.
3. COMPLETED의 기존 생성·재채점·미디어 분석·기업 피드백은 유지한다.
4. 중단 기록 전달의 outbox·재전송·보존은 제거하지 않는다.
5. 정책 생략을 장애 재시도·운영 오류로 반복 집계하지 않는다.
